# 项目构建说明

给智能体一句任务（比如「用记事本新建文件，写三行水果名保存」），它反复做四件事：截图看屏幕，
让多模态大模型决定下一步，用鼠标键盘执行，再看屏幕有没有变化，直到完成或放弃。模型用公开的
GUI 数据集做 LoRA 监督微调；效果用两类评测来量：离线数据集（逐步比对动作）和真实桌面任务
（跑完用程序验收）。

---

## 一、一次任务怎么跑

入口是 `scripts/run_tasks.py`（跑任务集）或 `scripts/run_agent.py`（跑一句话），核心循环在
`gui_agent/agent.py` 的 `Agent.run`，每一步：

1. **感知**（`perception.py`）：用 mss 截图，按模型的切块大小缩放。执行时不跑 OCR，屏幕上的字
   和控件都由模型自己看。
2. **规划**（`planner.py`，加 `--plan` 时）：第一次看到屏幕时，让模型看着截图把任务拆成最多 8 个
   子任务。之后每执行一步反思一次：子任务完成就进入下一个；没完成就接着做；连续 3 次没推进就按
   当前屏幕重新拆，最多重拆 2 次。结构沿用 ScreenAgent 的「规划—执行—反思」。
3. **决策**（`chain.py` + `models.py`）：把任务、当前子任务、最近 5 步历史填进提示词，交给模型，
   解析成动作 JSON。动作是 UI-TARS 桌面子集的 10 种：click、left_double、right_single、drag、
   scroll、type、hotkey、wait、finished、call_user。点击类动作分两段问：
   - 第一段只问「点什么」，模型回控件名，比如「文件菜单」；
   - 第二段用定位提示词让模型在截图上框出这个控件，框中心换算成屏幕坐标。

   「点什么」和「点哪」分开，定位走模型自带的能力，没有文字的图标也能点。
4. **执行**（`control.py`）：0~1 坐标换算成当前屏幕像素，pyautogui 点击、输入、按快捷键、拖拽、
   滚动；中文文本经剪贴板粘贴。会锁屏或打断会话的组合键（Ctrl+Alt+Delete、Win+L）和明显危险的
   命令文本直接拒绝；鼠标甩到屏幕左上角立即急停。
5. **反馈与容错**：执行后再截一张图与执行前比较，界面没变（比如点空了）会写进历史，下一步模型
   能看到。单步出错（截图失败、输出解析不了）最多连续重试 2 次；同一动作连续 3 次且界面不变判为
   卡住；步数有上限（`--max-steps`，`run_tasks.py` 默认 12）。
6. **记录**（`monitor.py`）：每步写一行 JSONL（动作、结果、耗时、子任务、反思），整条轨迹存进
   `logs/tasks_<标签>.json`。

任务跑完由 `tasks.py` / `suite.py` 里的验收函数判成败：比对执行前后的状态（文件内容、窗口标题、
进程、文件夹），不看模型自己说没说完成。

**执行时为什么不用 OCR。** 第 2、3 周用的是一段式：先用 EasyOCR 把屏幕文字编成带编号的元素清单，
模型回编号。图标没有文字就没有编号，Qwen2.5-VL 在 120 条 ScreenSpot 样本上一段式命中 40.8%，
两段式 62.5%。换成两段式以后元素清单在执行路径上用不到，去掉后 1280×720 下每步省 0.7 s，也不占
显存。OCR 代码留作两个用途：构建训练数据时给点击点匹配控件名；`--one-stage` 复现一段式对照。

## 二、代码目录

**`gui_agent/`：智能体本体**

| 模块 | 做什么 |
|---|---|
| `schema.py` | 三个数据格式：屏幕识别结果 `ScreenState`、动作 `Action`、执行记录 `Step` / `Trajectory` |
| `perception.py` | 截图、缩放、屏幕变化检测；OCR 和 OpenCV 图标候选框只在构建数据和一段式对照里用 |
| `planner.py` | 任务拆解与子任务反思 |
| `chain.py` | 用 LangChain 组装提示词 → 模型 → 解析；两段式的定位解析；提示词变体 |
| `models.py` | 模型接口：本地加载 `LocalQwenVL`、OpenAI 兼容 API `OpenAICompatVLM`、故障注入 `FlakyVLM` |
| `agent.py` | 执行循环、动作解析、重试、卡住判定 |
| `control.py` | 鼠标键盘执行与安全拦截 |
| `monitor.py` | 每步日志 |
| `display.py` | 临时切换屏幕分辨率，结束后还原 |
| `tasks.py` | 基础 5 个、复杂 4 个任务及验收函数 |
| `suite.py` | 第 7 周评测集：25 个任务，T1/T2/T3 三档 |

**`scripts/`：按用途**

| 用途 | 脚本 |
|---|---|
| 数据预处理 | `prepare_screenagent.py`、`prepare_mind2web.py`、`prepare_webarena.py`、`prepare_data.py` |
| 构建训练集 | `build_finetune_data.py`，审计 `audit_finetune_data.py` |
| 训练 | `train_lora.py` |
| 离线评测 | `eval_screenagent.py`、`eval_grounding.py`、`eval_plan.py`、`tune_prompt.py`、`eval_perception.py`、`analyze_by_app.py` |
| 在线运行 | `run_tasks.py`、`run_agent.py`、`snapshot_state.py` |
| 换模型 | `probe_model.py`（测新模型的坐标口径和输出格式） |
| 虚拟机实验 | `serve_vlm.py`、`vm/guest_worker.py`、`vm/host_jobs.py` |
| 报告 | `make_charts.py`、`gen_test_report.py`、`md2pdf.py` |

## 三、模型

- **基座**：Qwen2.5-VL-3B-Instruct。图片按 14×2 = 28 像素切块，定位坐标回的是缩放后图片的像素值。
  坐标口径由预训练决定、提示词改不了，所以换模型前先用 `probe_model.py` 实测再在
  `models.COORD_SPACE_BY_MODEL_TYPE` 里登记。

- **两种调用方式**：本地加载（bf16，可挂 LoRA 权重）；OpenAI 兼容 API（云服务，或虚拟机实验里
  宿主机上的 `serve_vlm.py`）。

- **视觉模型的结构**：视觉编码器（ViT）把截图切块编码，对齐层（merger）把视觉特征映射到语言模型
  的维度，和文字 token 拼成一条序列交给语言模型生成。本项目冻结 ViT 和对齐层，只微调语言模型：
  基座看图定位已经不差（ScreenSpot 桌面 71.6%），差在「这一步该做什么」。对齐层全量训练跑过对照，
  在 579 条数据上会把定位打坏，取舍见《微调方案设计》。

## 四、数据

| 数据集 | 用途 |
|---|---|
| ScreenAgent | 动作样本和拆解样本（人工修正过）；官方 test 划分 353 步做动作评测 |
| Mind2Web | 网页元素定位样本、任务拆解语料 |
| WebArena | 任务写法和验收方式的参照 |
| ScreenSpot 桌面 334 条 | 元素定位评测 |

`build_finetune_data.py` 把预处理后的数据变成对话样本（截图 + 提示词 → 回答）：

- **动作样本**：回答是 `{"thought": ..., "action": ...}`。两段式里点击类动作的位置写成控件名，
  控件名由 OCR 文字框和人工修正的点击点匹配出来（文字框外扩 0.01）。
- **拆解样本**：回答是子任务数组。提示词里元素清单一栏写「（这一步不看元素清单）」，和执行时、
  离线拆解评测时是同一句。
- 按动作类型的真实比例抽样、去掉完全重复的样本；`audit_finetune_data.py` 查错标、重复、泄漏。

交付配方用的 `data/finetune_2sp`：训练 559 条（动作 375、拆解 184），验证 89 条。

## 五、训练（`train_lora.py`）

- **分层微调**：ViT 冻结，对齐层全量训练（学习率 2e-4），语言模型挂 LoRA（学习率 1e-4）。
  `--lora-targets all` 覆盖 36 层的 `q/k/v/o_proj` 与 `gate/up/down_proj`，共 252 个投影、2990 万参数；
  对齐层 3671 万参数全部可训。
- 底座 4-bit 加载（QLoRA），进程显存上限 0.65，12 GB 卡上给其他程序留余量；实测峰值 6.27 GB。
- 只在回答部分算 loss，提示词和截图部分屏蔽；前向时只算回答段的 logits，省显存。
- **按验证损失取最优步，不训满。** 每 50 次更新在验证集上评一次，只有创新低时才写交付路径；
  周期性存点另存一份防中途中断。579 条数据上验证损失在第 150 步最低（1.1050），之后单调上升
  到第 400 步的 1.6232，固定训满会交付过拟合的权重。
- 交付配方：rank 16、语言模型学习率 1e-4、对齐层 2e-4、OneCycle、梯度累积 8、
  图片上限 640 个视觉 token、`--train-merger full --merger-lr 2e-4 --keep-best --eval-every 50`。
- 对齐层用 `--train-merger full`，该层不做 4-bit 量化（跳过列表要连 `lm_head` 一起写，
  否则它被量化后前向会断言失败）。只训语言模型的对照版跑过，流程内点击精度更低。

交付权重在 `checkpoints/q25_proj`（对齐层全量 + 语言模型 LoRA），对照权重在 `checkpoints/q25_lm`（只训语言模型）。
LoRA 权重只能挂回训练它的那个基座，挂错会直接报错。

## 六、评测

| 类型 | 评测集 | 脚本 | 指标 |
|---|---|---|---|
| 动作生成 | ScreenAgent test 353 步 | `eval_screenagent.py` | 动作类型准确率、键盘动作召回、点击距离、类型对且点准 |
| 元素定位 | ScreenSpot 桌面 334 条 | `eval_grounding.py` | 预测点落在真值框内的比例 |
| 任务拆解 | ScreenAgent 留出 20 条 | `eval_plan.py` | 与参考拆解的字符级 F1 覆盖率 |
| 提示词工程 | ScreenAgent test 前 60 步 | `tune_prompt.py --mode two_stage` | 两段式各提示词变体的动作类型准确率、类型对且点准 |
| 感知模块 | ScreenSpot 桌面 | `eval_perception.py` | 第 3 周一段式用：OCR 与候选框覆盖率、耗时 |
| 不同应用 | ScreenAgent test 按应用分 7 类 | `analyze_by_app.py` | 分类准确率 |
| 端到端 | 基础 5、复杂 4、评测集 25 个 | `run_tasks.py` | 成功率、平均执行时间、错误率 |
| 容错 | 基础 5 个 + 30% 故障注入 | `run_tasks.py --inject-failures 0.3` | 开 / 关重试时被故障终止的任务数 |

离线评测逐条记录在 `logs/` 的 JSON 里；`make_charts.py` 从这些日志画图到 `docs/figures/`。

## 七、安全与环境恢复

- 默认 dry-run，只打印动作；加 `--live` 才真的操作。
- 任务文件只在 `logs/scratch/` 里读写；只关脚本自己启动的程序。
- 分辨率临时切到 1280×720，结束后自动还原；`snapshot_state.py` 在实验前后核对分辨率、进程和窗口。
- 真实桌面实验两种跑法。直接在本机跑时按固定步骤来：先确认没有聊天软件（托盘里的也算）和可见的
  浏览器窗口，存桌面状态和进程表，最小化窗口，跑完恢复窗口、只关实验期间新开的任务类程序，再用
  `snapshot_state.py --check` 核对。要无人值守或要每次都从干净状态开始，就放进虚拟机：模型留在宿主机
  显卡上（`serve_vlm.py`），虚拟机里的 `guest_worker.py` 领任务，宿主机 `host_jobs.py` 暂停显卡队列、
  恢复快照、投任务、收结果，步骤见 `docs/虚拟机评测指南.md`。

## 八、常用命令

离线评测脚本保留 `--locate-target` 开关（不加就是一段式），这样第 2、3 周的一段式对照用同一个脚本
就能复现；执行用的 `run_tasks.py` / `run_agent.py` 已经默认两段式。

```
# 离线评测（Qwen2.5-VL 基座 / 挂上微调权重）
python scripts/eval_screenagent.py --model Qwen/Qwen2.5-VL-3B-Instruct --locate-target --max-new-tokens 256 --tag q25_base_2s
python scripts/eval_screenagent.py --model Qwen/Qwen2.5-VL-3B-Instruct --adapter checkpoints/q25_lm --locate-target --max-new-tokens 256 --tag q25_lm_2s
python scripts/eval_grounding.py   --model Qwen/Qwen2.5-VL-3B-Instruct --tag q25_base

# 提示词变体（两段式）
python scripts/tune_prompt.py --mode two_stage --model Qwen/Qwen2.5-VL-3B-Instruct --limit 60 --tag q25_2s

# 训练（交付配方）
python scripts/train_lora.py --model Qwen/Qwen2.5-VL-3B-Instruct --data-dir data/finetune_hist --kinds action,plan ^
    --epochs 6 --rank 16 --lr 1e-4 --accum 8 --max-pixels 640 --load-in-4bit --mem-fraction 0.65 --tag q25_lm

# 端到端（默认基座 Qwen2.5-VL、默认两段式、不跑 OCR；dry-run 先看动作，再加 --live）
python scripts/run_tasks.py --set suite --adapter checkpoints/q25_lm
python scripts/run_tasks.py --set suite --adapter checkpoints/q25_lm --live --resolution 1280x720 --tag live_q25_lm
python scripts/summarize_suite.py          # 成功率、平均耗时、错误率三张表

# 图表与测试
python scripts/make_charts.py
pytest tests/ -q
```
