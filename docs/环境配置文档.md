## Python 环境

用 Anaconda base 环境（Python 3.10.9），没有新建虚拟环境。原因是 base 里已经装好 torch 2.6.0+cu124，新建环境要重新下载约 2.5GB 的 CUDA 版 torch。

代价是 base 与其他项目共用，装包时容易互相影响，第一次安装就撞上了（见下面「踩过的坑」第 2 条）。如果后面冲突变多，再迁到独立环境。

## 安装

```bash
pip install -r requirements.txt
python scripts/check_env.py          # 快速检查
python scripts/check_env.py --ocr    # 额外实测 OCR，首次会下载模型权重
```

## 踩过的坑

**1. transformers 无法导入（环境原有问题，非本次安装引入）**

报错 `cannot import name 'is_offline_mode' from 'huggingface_hub'`。环境里 transformers 是 5.3.0，要求 huggingface-hub>=1.3.0，但实际装的是 0.33.1。

对比安装日志确认，huggingface-hub 在本次安装过程中始终没有被改动，是环境原有状态。

解决：`pip install "huggingface-hub>=1.3.0,<2.0"`，升到 1.28.0 后正常。

**2. numpy 被顶到 2.x，导致 OCR 和其他项目一起挂掉**

装 easyocr 时，它的依赖 opencv-python-headless 5.x 要求 numpy>=2，pip 就把 numpy 从 1.26.4 升到了 2.2.6。后果：

- easyocr、paddleocr 报 `numpy.dtype size changed, may indicate binary incompatibility` —— 这两个包是针对 numpy 1.x 编译的
- pandas 导入时 numexpr 报 `_ARRAY_API not found`
- base 环境里的其他项目（trading-agent 要求 numpy<2）也被打断

解决：把 numpy 钉回 1.26.4，同时把 opencv-python-headless 降到 4.10.0.84（4.x 不要求 numpy 2）。requirements.txt 里这两条是硬约束，不要放开。

**3. opencv 版本被 paddlex 锁定**

装 paddleocr 会连带装 paddlex，paddlex 锁定 `opencv-contrib-python==4.10.0.84`，把原有的 4.11.0.86 降了下来。目前没有引发问题，记录备查。

## 实测结果

`python scripts/check_env.py --ocr`，19 项全部通过。

| 项 | 结果 |
|---|---|
| Python | 3.10.9 |
| PyTorch | 2.6.0+cu124，CUDA 可用 |
| CUDA 实算 | 2048×2048 矩阵乘 118.8 ms |
| 显存 | 12.0GB，空闲 10.8GB |
| mss 截图 | 3840×2160，平均 75.1 ms/帧 |
| pyautogui | 报告屏幕尺寸 3840×2160 |
| 坐标系 | 截图尺寸与控制尺寸一致 |
| easyocr 实测 | 全屏识别出 285 处文字，耗时 9.7s（GPU） |
| 其余库 | pynput、OpenCV 4.10、transformers 5.3.0、peft、accelerate、bitsandbytes、datasets、langchain、matplotlib、paddleocr 均正常 |

两点结论：

**1. 坐标系不需要换算。** 之前用 ctypes 在 DPI 不感知的情况下测，系统报告的屏幕是 2194×1234，与截图的 3840×2160 差 1.75 倍。但实际装好 pyautogui 0.9.54 后，它报告的就是 3840×2160，与 mss 一致，不存在偏移。感知模块内部仍然用 0 到 1 的相对坐标，但那是为了适配模型输入尺寸，不是为了修 DPI。

**2. 全屏 OCR 太慢，不能每步都跑。** 4K 全屏 9.7 秒，Agent 循环里每步都识别一次不现实。截图本身 75ms 也偏慢。后续要做的：截图前先缩放，或只识别发生变化的区域。这项对应大纲第 6 周第 3 项「优化屏幕感知模块，提升 UI 元素识别的准确率与速度」，现在这两个数字就是优化的起点。
