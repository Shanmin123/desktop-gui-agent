## 二、数据集

大纲点名的三个都不能直接用：ScreenAgent 在 HuggingFace 上没有、GitHub 仓库页也没给下载链接；WebArena 是需要自建 Docker 网站的运行环境，不是数据集；Mind2Web 是 6.28 GB 的 HTML DOM 数据不含截图，带截图的版本 12.64 GB，且都是 Web 域。

改用两个桌面 grounding 数据集，合计约 1 GB：

| 数据集 | 用途 | 数量 |
|---|---|---|
| `rootsautomation/ScreenSpot` 桌面分片 | 定位精度评测 | 334（Windows 162 / macOS 172） |
| `showlab/ShowUI-desktop` | 微调训练 | 训练 6747 / 验证 749 |

两者的 bbox 都是归一化 `[x1,y1,x2,y2]`，与第 1 周定的数据格式一致，不需要转换。已抽样把框画回原图人工核对。

## 三、系统组成

**模型**：本地 Qwen2.5-VL-3B-Instruct，bf16，显存占用 6.99 GB，单次推理 2.6 s。大纲清单里 Qwen-VL-Chat 和 GLM-4V-9B 权重 18 GB 与 25.9 GB，Llama-3.2-Vision 在 HuggingFace 上需要申请许可。

**Agent 循环**：ScreenAgent 的 Planning-Acting-Reflecting。每步截图并 OCR，把任务、执行历史、带编号的元素清单组成提示词，模型返回 Thought 和 Action，执行后结果写回历史。

模型用元素编号指定目标，由 Agent 查表换成归一化坐标。编号是本项目自己编的，不经过模型的坐标空间。模型直接给坐标时，超出 0~1 的按其 `smart_resize` 尺寸换算。

**终止条件**：任务完成、动作失败、连续 3 步重复同一动作、达到步数上限。

**安全**：默认 dry-run 只打印动作；文件操作限制在 `logs/scratch/`；危险组合键黑名单；FAILSAFE。

## 四、基础任务测试

五个任务各跑一次，`scripts/run_tasks.py --live`。

| 任务 | 结果 | 步数 | 耗时 |
|---|---|---|---|
| open_browser | 通过 | 11 | 38.5 s |
| search_content | 不通过 | 9 | 23.8 s |
| open_file | 不通过 | 4 | 10.0 s |
| type_and_save | 不通过 | 4 | 10.8 s |
| close_app | 不通过 | 10 | 32.6 s |

**成功率 1/5 = 20%**，平均 7.6 步、23.1 s。这是 v1.0 基线，第 3 周微调和优化后跑同一套任务对比。

每个任务的验收都是程序判断，且对比执行前后的状态差异：新出现的浏览器进程、新增的窗口标题、文件内容、进程从有到无。只看当前状态会把「本来就是这样」判成成功。

大纲的「发送消息」改成在记事本输入并保存到本地文件。真向他人发消息不可逆且对外，不适合让还在调试的智能体执行。验收改看文件内容，比「消息已发出」更严格。

### 失败归因

37 个动作里，双击 31 次、单击 3 次、`type` 和 `hotkey` **各 0 次**。

模型完全没有使用键盘动作，连「在记事本里输入你好」这种必须打字的任务也在反复双击。几个任务结构上无法完成。四个任务是靠卡住检测中止的，说明模型在界面没有按预期变化时不会换策略。

这指向第 3 周的两项工作：提示词里补充键盘动作的使用场景和示例，微调数据里增加非点击类动作的样本。
