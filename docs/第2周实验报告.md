## 三、系统组成

**模型**：本地 Qwen2.5-VL-3B-Instruct，bf16，显存 7.0 GB。端到端每步平均 3.0 s，含截图、OCR、推理和动作执行。

**Agent 循环**：ScreenAgent 的 Planning-Acting-Reflecting。每步截图并 OCR，把任务、执行历史、带编号的元素清单组成提示词，模型返回 Thought 和 Action，执行后结果写回历史。模型用元素编号指定目标，由 Agent 查表换成归一化坐标；直接给坐标时，超出 0~1 的按其 `smart_resize` 尺寸换算。

**终止条件**：任务完成、动作失败、连续 3 步重复同一动作、达到步数上限。

**安全**：默认 dry-run 只打印动作不执行；任务涉及的文件读写都在 `logs/scratch/`；锁屏类组合键和形似破坏性命令的输入直接拒绝；鼠标甩到屏幕角落触发 FAILSAFE 中断。

## 四、基础任务测试

五个任务各跑一次，`scripts/run_tasks.py --live`。

| 任务 | 结果 | 步数 | 耗时 |
|---|---|---|---|
| open_browser | 通过 | 11 | 38.5 s |
| search_content | 不通过 | 9 | 23.8 s |
| open_file | 不通过 | 4 | 10.0 s |
| type_and_save | 不通过 | 4 | 10.8 s |
| close_app | 不通过 | 10 | 32.6 s |

**成功率 1/5 = 20%**，平均 7.6 步、23.1 s。

验收由程序判断，比对执行前后的状态差异：新出现的浏览器进程、新增的窗口标题、文件内容、进程从有到无。

大纲的「发送消息」改成在记事本输入并保存到本地文件，验收看文件内容：真发消息不可逆且对外。

### 失败归因

38 步里双击 31 次、单击 3 次，`type` 和 `hotkey` **各 0 次**，另有 4 条 `call_user` 终止记录。

模型不用键盘，连「在记事本里输入你好」也在反复双击；界面没按预期变化时也不换策略，只是继续点。

这指向下周的两项工作：提示词里补充键盘动作的使用场景和示例，微调数据里增加非点击类动作的样本。

## 五、UI 元素定位精度基线

在 ScreenSpot 桌面分片全量 334 条上评测，判定标准是模型给出的点落在真值框内。

| 分组 | 命中 / 总数 | 准确率 |
|---|---|---|
| 总体 | 239 / 334 | **71.6%** |
| 文字类 | 161 / 194 | 83.0% |
| 图标类 | 78 / 140 | 55.7% |
| Windows | 112 / 162 | 69.1% |
| macOS | 127 / 172 | 73.8% |

平均单条 1.68 s，坐标解析失败 0 条。

文字类和图标类差 27 个百分点，与基础任务里的表现一致：模型倾向于在能读到文字的地方点击，遇到图标就开始试探。

下周微调按图标类加权采样。任务成功率 20% 和定位精度 71.6% 是 v1.0 基线，微调后跑同一套任务和评测集对比。
