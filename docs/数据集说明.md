# 数据集说明

对应大纲第 3 周第 1 项。

## 大纲点名的三个

| 数据集 | 获取方式 | 内容 |
|---|---|---|
| ScreenAgent | 数据随 GitHub 仓库发布，`git clone` 即可，仓库 270 MB。HuggingFace 上只有模型权重 `niurl/ScreenAgent`，没有数据集条目 | 桌面操作轨迹。`train/` 下 203 个 session 目录，测试集打包在 `test.zip`，截图与标注 JSON 配对，全部 1024×768 |
| WebArena | `config_files/test.raw.json`，812 条任务规格 | 任务定义，不含截图。要运行须先用 docker 自建购物站、Reddit、GitLab、地图、维基 |
| Mind2Web | `osunlp/Multimodal-Mind2Web` 13.6 GB（带截图）；`osunlp/Mind2Web` 6.74 GB（只有 HTML DOM） | 网页操作轨迹，Web 域 |

三个的形式不一样，用途也不同。

## ScreenAgent：微调主力

`python scripts/prepare_screenagent.py --src <仓库>/data/ScreenAgent`

原始记录是会话里的一步：截图 + 提示词 + 模型输出 + 人工修正后的动作。按 ScreenAgent 的约定，训练用修正后的 `actions`。

原始动作 6346 条，其中能对应到本项目 10 个动作的 1540 条：

| 转换后 | 条数 | | 转换后 | 条数 |
|---|---|---|---|---|
| click | 679 | | type | 281 |
| hotkey | 323 | | left_double | 105 |
| wait | 67 | | scroll | 55 |
| right_single | 30 | | | |

未转换的：`PlanAction` 2830 条和 `EvaluateSubTaskAction` 1856 条是自然语言的计划与反思，不对应可执行动作；`move` / `down` / `up` 是拆开的鼠标原语，`drag` 只记了落点没有起点，凑不出本项目的动作。

**键盘动作 604 条**（`type` 281 + `hotkey` 323）。这是三个数据集里唯一一批桌面域的键盘操作样本。

这 1540 条来自 272 个 session。官方已经分好 train / test，**测试集整份留作评测**，不参与训练也不参与验证——合起来重新划分会把测试样本混进训练池，微调后拿它评测出来的数字就是污染的。

训练部分内部再按 session 切出验证集，同一次会话不跨两边，避免同一屏的画面在训练和验证里都出现：

| 划分 | 条数 | session |
|---|---|---|
| train | 1082 | 182 |
| val | 105 | 20 |
| test（留出） | 353 | 70 |

脚本会检查三个划分之间有没有相同的 session，有就直接报错退出。

`data/screenagent/samples/` 是抽样画框的结果，已人工确认标记落在动作描述的控件上。

键名是 X11 keysym（`Return`、`Control_L`），`gui_agent/control.py` 的别名表已补上这一套，转换出来的组合键能直接执行。

## WebArena：任务设计与验收方式的参照

`python scripts/prepare_webarena.py`

没有截图，做不了多模态微调数据。可用的是两样：

| 项 | 数量 |
|---|---|
| 任务指令 | 812 条，190 个参数化模板 |
| 站点 | gitlab 204、shopping 192、shopping_admin 184、reddit 129、map 128、wikipedia 23 |
| 验收方式 | program_html 411、string_match 335、url_match 205 |

大纲第 7 周要设计 20 个不同难度的桌面任务，这批指令和它的三种程序化验收方式是现成的参照。

## Mind2Web：任务拆解的补充语料

`python scripts/prepare_mind2web.py`

train 划分 7775 步、1009 条任务，每条 2~37 步、平均 7.7 步。

| 操作类型 | 条数 | | 领域 | 条数 |
|---|---|---|---|---|
| CLICK | 6337 | | Travel | 4082 |
| TYPE | 936 | | Shopping | 2309 |
| SELECT | 326 | | Entertainment | 1384 |
| HOVER | 164 | | | |
| ENTER | 12 | | | |

13.6 GB 几乎全在截图和原始 HTML 上，处理时只读元数据那几列、不解码截图，截图留在 HuggingFace 缓存里按行号取。

这是 Web 域的数据，不用于桌面定位训练。取的是「任务 → 步骤序列」这一层：1009 条任务的完整拆解，对应大纲第 3 周第 3 项的任务拆解与规划能力。它的 SELECT 和 HOVER 在桌面动作空间里没有对应，这两类不进训练样本。

## 评测基准

两个，都只出数字、不进训练集。

**ScreenAgent 的 test 划分**（353 条）是主基准：桌面域、任务级指令，测的是动作生成。`scripts/eval_screenagent.py`，v1.0 的动作类型准确率 42.2%、键盘动作召回 46.6%。

**ScreenSpot 桌面部分**（334 条）作参照：`rootsautomation/ScreenSpot` 602 MB，只有一个 test split 共 1272 条，覆盖 iOS / Android / macOS / Windows / Web，按 `data_source` 取 windows 和 macos。指令直接点名目标控件，判定是点落在真值框内，v1.0 是 71.6%。

两个数字不可比：后者告诉模型要点哪个控件，前者要模型自己从整条任务判断这一步该点哪。微调后两个都跑同一批对比。

## 转换目标

统一转成 `gui_agent/schema.py` 的格式：截图存盘，目标位置转成归一化到 0~1 的坐标，可执行的操作转成 `Action`。这样同一套结构在微调和评估里都能直接用。
