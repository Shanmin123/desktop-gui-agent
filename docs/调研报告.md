## 一、UI-TARS

来源：[arXiv:2501.12326](https://arxiv.org/abs/2501.12326)

### 1. 定位

端到端的原生 GUI 智能体模型，只接收截图作为输入，直接输出鼠标键盘操作，不依赖外部框架去包装商用模型。论文对比的是"用 GPT-4o 加人工提示词和工作流"这类方案，结论是端到端模型更好。

OSWorld 上 50 步得分 24.6、15 步 22.7，对应 Claude 的 22.0 和 14.9；AndroidWorld 46.6，对应 GPT-4o 的 34.5。

### 2. 统一动作空间（Table 1）

跨平台通用：

| 动作 | 说明 |
|---|---|
| `Click(x, y)` | 点击 |
| `Drag(x1, y1, x2, y2)` | 从一点拖到另一点 |
| `Scroll(x, y, direction)` | 在指定位置滚动 |
| `Type(content)` | 输入文本 |
| `Wait()` | 短暂等待 |
| `Finished()` | 任务完成 |
| `CallUser()` | 请求人工介入 |

仅桌面端：

| 动作 | 说明 |
|---|---|
| `Hotkey(key)` | 组合键 |
| `LeftDouble(x, y)` | 双击 |
| `RightSingle(x, y)` | 右键 |

仅移动端：`LongPress`、`PressBack`、`PressHome`、`PressEnter`。

**坐标用相对值，按屏幕尺寸归一化**，论文的说法是这样能在不同分辨率的设备之间保持一致。

### 3. 屏幕感知

只用截图，论文里没有提 OCR、也没有提无障碍树。

### 4. 输出格式

每一步同时输出 Thought 和 Action，一条轨迹写成 `(instruction, (o₁,t₁,a₁), (o₂,t₂,a₂), …, (oₙ,tₙ,aₙ))`，其中 o 是观察、t 是推理、a 是动作。

### 5. 四项主要工作

1. 增强感知：用大规模 GUI 截图数据集训练对 UI 元素的理解和描述。
2. 统一动作建模：把动作标准化成一个跨平台的空间，用大规模操作轨迹训练定位和交互。
3. System-2 推理：在多步决策中加入任务拆解、反思、里程碑识别等推理模式。
4. 反思式在线轨迹迭代训练：在数百台虚拟机上自动采集、过滤、修正新轨迹，让模型从自己的错误里学。

## 二、Claude Computer Use

来源：[官方文档](https://platform.claude.com/docs/en/agents-and-tools/tool-use/computer-use-tool)

### 1. 动作列表

一共 17 个：

- 截图类：`screenshot`、`zoom(region)`
- 鼠标点击：`left_click`、`right_click`、`middle_click`、`double_click`、`triple_click`，参数是 `coordinate` 和可选的修饰键 `text`（shift / ctrl / alt / super）
- 鼠标其他：`left_click_drag(start_coordinate, coordinate)`、`mouse_move`、`left_mouse_down`、`left_mouse_up`、`cursor_position`
- 滚动：`scroll(scroll_direction, scroll_amount, coordinate)`
- 键盘：`type(text)`、`key(text, repeat)`、`hold_key(text, duration)`
- 等待：`wait(duration)`

### 2. 坐标系

坐标是**截图的像素坐标**，原点在左上角，不归一化。`zoom` 之后模型给出的坐标仍然是整屏坐标系里的，不是放大图里的。如果自己把截图缩小了送模型，拿到坐标要按比例放大回去再执行。

这一点和 UI-TARS 相反：UI-TARS 用归一化相对坐标，Claude 用绝对像素坐标加外部换算。

### 3. 分辨率限制

推荐的桌面分辨率是 1024×768 或 1280×720，不建议超过 1920×1080。

API 对图片有硬限制，超了会报错：

| 模型 | 长边上限 | 总像素上限 |
|---|---|---|
| Opus 4.7+ | 2576 px | 约 3.75 MP |
| 更早的模型 | 1568 px | 约 1.15 MP |

文档给的缩放系数算法是取三者最小值：`1.0`、`长边上限/长边`、`sqrt(总像素上限/总像素)`。

### 4. 提高点击准确率的做法

- 提示词里把文字说明放在截图**前面**，能提升点击准确率。
- 小目标或者缩得太狠的截图，用 `zoom` 对局部再看一次全分辨率。

## 三、两条路线的差异

| | UI-TARS | Claude Computer Use |
|---|---|---|
| 形态 | 端到端模型，专门训练 | 通用模型 + 工具接口 |
| 感知 | 只看截图 | 只看截图，但可以 `zoom` 局部 |
| 坐标 | 归一化相对坐标 | 截图像素坐标，缩放换算交给调用方 |
| 动作数量 | 桌面 10 个 | 17 个 |
| 推理 | 模型自带 Thought | 靠提示词 |

## 四、对本项目的影响

**动作格式**：本项目只做桌面端，打算直接用 UI-TARS 的桌面子集，共 10 个动作：`Click`、`LeftDouble`、`RightSingle`、`Drag`、`Scroll`、`Type`、`Hotkey`、`Wait`、`Finished`、`CallUser`。理由是第 3 周要用公开数据做微调，动作格式和 UI-TARS 对齐可以少一层转换。同时保留 Claude 的 `zoom` 思路，作为定位不准时的补救手段。

**坐标**：跟 UI-TARS 用归一化相对坐标。8/24 实测本机 pyautogui 和 mss 报告的屏幕尺寸一致，都是 3840×2160，不存在 DPI 偏移，所以归一化不是为了修坐标系，是为了让模型输出与屏幕分辨率解耦。

**截图分辨率**：本机 3840×2160 是 8.3 MP，远超上述限制，必须缩放后再送模型。按文档的算法，若参照 1568 px / 1.15 MP 这档，缩放系数取 `min(1568/3840, sqrt(1150000/8294400)) = min(0.408, 0.372) = 0.372`，缩放后约 1428×803。这个值和 8/24 实测的 easyocr 全屏耗时 9.7 秒放在一起看：缩放既是模型输入的要求，也顺带解决感知太慢的问题。
