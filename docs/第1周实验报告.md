## 四、本周的五个问题

**1. cv2 在中文路径下存图静默失败**

项目目录名是中文，`cv2.imwrite` 按 ANSI 代码页处理路径，返回 False 但不抛异常，文件没写出来。脚本打印了"已存到"，目录里却是空的。`cv2.imread` 同理。改成 `imencode` 加 Python 文件接口，全项目统一走 `perception.imwrite` / `imread`。

**2. OCR 不能在缩放图上跑**

原本设计成缩放后再 OCR，以为能顺带提速。实测原图 2.43 秒识别 65 处，缩放图 1.55 秒只剩 22 处。easyocr 检测阶段内部本来就把长边压到 2560，再往下缩就低于它的工作分辨率。省 0.88 秒不值丢三分之二的文字，改成缩放只用于模型输入，OCR 走原图。

**3. pyautogui 打不出中文**

`KEYBOARD_KEYS` 里全是 ASCII，`write()` 对中文直接忽略。按 `text.isascii()` 分流，含中文的走剪贴板加 Ctrl+V。ScreenAgent 也是这个解法。

**4. 文本黑名单会误伤正常输入**

安全拦截最初写成子串匹配，`"format "` 把 `format the paragraph` 也拦了。改成锚定开头的正则。更根本的问题是同一段文字打进 Word 无害、打进 cmd 危险，光看文本判断不了上下文，所以这道防线只能挡最明显的情况，真正的保障是 dry-run、FAILSAFE 和虚拟机。

**5. 坐标校准一度测出 623 px 误差**

排查后是外部干扰：有别的程序在同时移动光标。单独跑纯移动测试，SetCursorPos、pyautogui duration=0、duration=0.1 三种方式在 15 个点上都是零误差。校准脚本加了重试和干扰检测，不再把干扰误报成缩放系数问题。

另外环境里 transformers 5.3.0 与 huggingface-hub 0.33.1 本来就不兼容，装依赖时顺带修了；easyocr 会把 numpy 顶到 2.x，导致 OCR 和其他项目一起挂，已钉回 1.26.4。
