## 二、技术选型

读完 UI-TARS、Claude Computer Use、ScreenAgent 后定下五项，详见调研报告第五节。

| 项 | 结论 |
|---|---|
| 屏幕内容怎么送模型 | 缩放后的截图，附 OCR 元素列表，不用无障碍树 |
| 动作格式 | UI-TARS 桌面子集 10 个动作，坐标归一化到 0~1 |
| 任务规划 | ScreenAgent 的 Planning-Acting-Reflecting，每步先出 Thought |
| 主干模型 | 按大纲清单，第 2 周接入时实测显存再定规格 |
| 评估 | 每个任务配一个程序能判断的成功条件 |

动作格式在 8/26 就冻结了。后面控制模块按它实现、Agent 按它解析、微调数据按它标注、评估日志按它记录，改一次就要全线返工，所以先定死。

## 三、实测数据

环境：Windows 11，RTX 4080 Laptop 12GB，Python 3.10.9，PyTorch 2.6.0+cu124，屏幕 3840×2160。

| 项 | 结果 |
|---|---|
| 截图（mss） | 60–110 ms/帧 |
| 缩放到 1430×804 | 3.4 ms |
| OCR 原图 | 2.43 s，识别 65 处 |
| OCR 缩放图 | 1.55 s，识别 22 处 |
| 纯控制链路误差 | 15 个网格点全部 0 px |
| 含感知的完整链路 | 9 个点中 5 个 0 px，其余 2–23 px（伴随重试，判定为外部干扰）|

缩放系数按 Claude 文档的算法算出 0.372，3840×2160 缩到 1430×804。

## 四、遇到的问题

- cv2 在中文路径下存图返回 False 但不抛异常，文件没写出来。已统一封装 `imwrite` / `imread` 并加测试。
- OCR 在缩放图上识别率明显下降。改为缩放只用于模型输入，OCR 走原图。
- pyautogui 打不出中文。含中文的输入走剪贴板。
- 安全拦截的文本黑名单最初误伤正常输入。改为锚定开头的正则。
- 坐标校准一度测出大误差，排查后是外部程序在同时移动光标。脚本加了重试和干扰检测。
- 环境里 transformers 与 huggingface-hub 版本本就不兼容，easyocr 又会把 numpy 顶到 2.x。都已处理，版本约束写进 `requirements.txt`。

细节见 `docs/环境配置文档.md`。
